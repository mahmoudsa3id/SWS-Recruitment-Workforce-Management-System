# حالة تنفيذ SWS Clean Rebuild

المشروع أُنشئ كقاعدة جديدة، ولا يعتمد على مجلدات `part` لتقسيم التطبيق. كل Feature رئيسية مفصولة إلى `domain` و`data` و`presentation`، مع درجات متفاوتة من اكتمال حالات الاستخدام والشاشات.

## الموجود في الحزمة

- Auth: تسجيل الدخول، تسجيل الخروج، والتحقق من أن الحساب نشط ودوره admin.
- Dashboard: ملخصات الخزنة وأعداد المسافرين والمرتبات من RPC على الخادم.
- Travelers: القائمة، إنشاء وتعديل ملف، المراحل الأربع، سجل الدفعات، إضافة دفعة، وملف مسافر مع فئات المستندات.
- Documents: رفع/عرض المستندات من private bucket باستخدام Storage API وروابط مؤقتة.
- Finance: حركة الخزنة، الإيرادات العامة، وعكس حركة مع سبب وسجل تدقيق.
- Expenses: إدخال المصروفات وربطها بالحركة النقدية.
- Payroll: الاستحقاق والعمولات والخصومات، تسجيل المدفوعات الجزئية، وإظهار المتبقي.
- Monthly closing: إقفال وإعادة فتح الشهر مع السبب وسجل التدقيق.
- Reports: تقرير مالي شهري وتصدير PDF عربي وملف Excel قابل للتحرير (لم يُختبر تشغيله بعد).
- Audit وSettings: قراءة سجل العمليات وإعدادات التطبيق المتاحة.
- Traveler export: ZIP بملخص الحساب PDF والمستندات الأصلية لكل المسافر.
- SQL migrations، bootstrap-admin script، كاش JSON محدود المدة، واختبارات وحدات أولية.

## ما لا يصح اعتباره مكتملًا/مُعتمدًا للإنتاج

- لم تتوفر Flutter/Dart SDK عند إعداد الأرشيف؛ لم ينفذ التحليل أو الاختبارات أو بناء Web/Windows.
- لم تختبر SQL/RLS/RPC على قاعدة Supabase فعلية.
- PDF العربي وتصدير المسافر يجب مراجعتهما بصريًا بعد التشغيل.
- لا توجد pagination تفاعلية للمسافرين،  ولا حفظ ثنائي دائم لكل مستند مفتوح أو مزامنة offline للكتابات.

استخدم `README_AR.md` و`KNOWN_LIMITATIONS_AR.md` كمرجع إعداد وتحقيق قبل الإنتاج.
