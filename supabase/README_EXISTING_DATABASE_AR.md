# تحديث SWS لقاعدة موجودة — مهم

هذا التحديث مخصص لقاعدة Supabase الحالية التي تحتوي على بيانات فعلية.

1. خذ نسخة احتياطية من قاعدة البيانات أولاً من Supabase Dashboard.
2. افتح `supabase/migrations/202610180001_sws_safe_traveler_delete.sql`.
3. راجع الملف، ثم الصقه في SQL Editor للمشروع الحالي واضغط Run.
4. لا تشغّل `INSTALL_ALL_MIGRATIONS.sql` على قاعدة البيانات الحالية؛ فهو حزمة تثبيت شاملة لقاعدة جديدة/اختبارية.
5. بعد نجاح الترحيل، شغّل التطبيق. خيار حذف المسافر يطلب سببًا، ويسجل لقطة تدقيق قبل حذف المسافر والحركات المرتبطة.
6. يرفض الحذف إذا كانت أي حركة مرتبطة في شهر مقفول أو إذا اكتشف ارتباطًا غير متوقع بمصروف أو مرتب.
7. ملفات Storage تُحذف عبر Storage API من التطبيق. لو فشل حذف الملفات، تبقى مساراتها في `sws_storage_cleanup_queue` لإعادة المحاولة لاحقًا؛ لا يستطيع PostgreSQL حذف ملفات Storage ضمن نفس المعاملة.

الترحيل لا يحذف أي سجلات قديمة عند تطبيقه؛ هو ينشئ دوال الحذف وطابور تنظيف الملفات فقط. الحذف الفعلي لا يحدث إلا عندما يؤكد الأدمن عملية حذف مسافر من التطبيق.
